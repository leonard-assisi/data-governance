Databricks Unity Catalog

데이터 계층구조, 사용자 이용 흐름, 거버넌스 관리 체계

1. 데이터 계층구조

아키텍처 구조

Databricks Unity Catalog는 관리 계층(Account)과 데이터 포함 계층(Metastore→Catalog→Schema→Objects), 그리고 컴퓨팅 환경(Workspace)으로 구성됩니다. Workspace는 Metastore에 연결되어 데이터에 접근합니다.

Account (계정 관리 계층)
조직 최상위 - Metastore와 Workspace 관리
↓ 관리
Metastore (데이터 포함 계층)
메타데이터 중앙 저장소 - 리전별
↓ 포함
Catalog
데이터 최상위 논리 그룹
↓ 포함
Schema
도메인별 객체 그룹
↓ 포함
Objects
테이블, 뷰, 볼륨 등
Workspace (컴퓨팅 환경)
팀별 작업 환경
↔ 연결 (N:1)

연결 관계:
• 1개 Workspace → 1개 Metastore
• 1개 Metastore ← N개 Workspace
• Workspace가 Metastore 내 Catalog 접근

계층별 역할

계층 역할
Account 조직 최상위, Metastore와 Workspace 관리
Metastore 메타데이터 저장소, Catalog 포함 (리전별)
Catalog 데이터 최상위 논리 그룹, Schema 포함
Schema 도메인별 객체 그룹, Objects 포함
Objects 실제 데이터 (테이블, 뷰, 볼륨 등)
Workspace 컴퓨팅 환경, Metastore에 연결하여 데이터 접근

관계 패턴

1:N 관계

1개 Metastore → N개 Workspace

여러 팀이 동일한 데이터 카탈로그를 공유하면서 각자 독립된 컴퓨팅 환경 사용

N:1 제약

1개 Workspace → 1개 Metastore만

각 Workspace는 하나의 Metastore에만 연결 가능. 리전 제약 존재.

데이터 접근 방법

Unity Catalog에서 데이터는 3단계 경로로 접근합니다:

데이터 경로 구조

카탈로그 → 스키마 → 테이블

예시:

  • prod.sales.orders → 운영환경의 판매 주문 데이터
  • dev.marketing.campaigns → 개발환경의 마케팅 캠페인 데이터

2. 사용자 이용 흐름

1

Workspace 접속

사용자는 할당된 Workspace에 로그인합니다. Workspace는 팀/프로젝트/환경(dev/staging/prod)별로 분리됩니다.

인증 권한 확인

2

Compute 리소스 준비

데이터 작업을 위한 Cluster를 생성하거나 기존 Cluster에 연결합니다.

  • All-Purpose Cluster: 대화형 개발, 애드혹 분석
  • Job Cluster: 자동화된 워크로드 (생성 후 자동 삭제)

Autoscaling Spot 인스턴스 Cluster Policy

3

개발 도구 선택

작업 유형에 따라 적절한 도구를 사용합니다:

Notebook

대화형 분석, ML 모델 개발, 프로토타이핑

SQL Editor

SQL 쿼리, 데이터 탐색, 대시보드

Job

스케줄된 워크플로우, 자동화 파이프라인

4

데이터 접근

Unity Catalog를 통해 데이터에 접근합니다. 권한이 있는 데이터만 조회할 수 있습니다.

접근 예시:

  • 운영환경의 판매 주문 데이터 조회
  • 고객별 구매 금액 합계 계산
  • 권한이 없는 데이터는 자동으로 차단됨
5

데이터 처리 및 저장

데이터 변환, 분석, ML 모델 학습 후 결과를 저장합니다.

데이터 처리

  • 원본 데이터 정제
  • 집계 및 분석
  • 결과를 새 테이블에 저장

모델 저장

  • ML 모델 학습
  • Volume에 저장
  • 버전 관리
6

협업 및 공유

같은 Metastore에 연결된 다른 Workspace 사용자들과 데이터 자동 공유. 외부 조직과는 Delta Sharing 활용.

실시간 협업 Delta Sharing 복사 불필요

권한 기반 접근 제어

모든 데이터 접근은 Unity Catalog의 권한 체계를 거칩니다. 권한이 없는 데이터는 조회/수정 불가능하며, 모든 접근 시도는 감사 로그에 기록됩니다.

3. 데이터 거버넌스 관리

3.1 접근 제어 (Access Control)

RBAC (역할 기반 접근 제어)

직책별로 권한을 부여하는 방식

  • 분석가 그룹: 판매 데이터 읽기 권한
  • 엔지니어 그룹: 모든 데이터 읽기/쓰기 권한
  • 매니저 그룹: 전체 데이터 조회 권한

→ "누구에게" 권한을 줄지 관리

ABAC (속성 기반 접근 제어)

사용자 속성에 따라 자동으로 권한이 변하는 방식

  • 부서별 필터: 자기 부서 데이터만 조회
  • 지역별 필터: 담당 지역 데이터만 접근
  • 민감 정보 마스킹: 권한 없으면 자동 가림

→ "어떤 데이터를" 볼 수 있는지 자동 결정

세분화된 보안 (Fine-Grained Security)

Row-Level Security (행 수준 보안)

예시: 고객 주문 테이블

  • 서울지점 직원 → 서울 고객 주문만 조회
  • 부산지점 직원 → 부산 고객 주문만 조회
  • 본사 매니저 → 전체 주문 조회

같은 테이블인데 사용자마다 보이는 데이터가 다름

Column Masking (열 마스킹)

예시: 고객 정보 테이블

  • 일반 직원 → 이메일 "abc***@***"로 표시
  • 관리자 → 이메일 "abc@example.com" 전체 표시
  • 전화번호도 같은 방식으로 마스킹

민감한 개인정보 자동 보호

3.2 데이터 계보 추적 (Data Lineage)

자동 계보 추적

모든 데이터 읽기/쓰기 작업을 자동으로 추적하여 데이터 흐름을 시각화합니다.

추적 수준 범위 활용
테이블 수준 모든 읽기/쓰기 작업 업스트림/다운스트림 의존성 파악
열 수준 SQL 변환 추적 열 간 데이터 흐름 추적
노트북/Job 실행 컨텍스트 어떤 작업이 데이터를 생성/변경했는지

보관 기간

  • Explorer 에디션: 30일
  • Premium 플랜: 5년

제약사항

  • PySpark DataFrame: 부분 추적
  • 외부 테이블: 제한적 계보
  • 레거시 Hive 메타스토어: 일부 제외

3.3 감사 및 컴플라이언스 (Audit & Compliance)

감사 로깅

모든 데이터 접근, 권한 변경, 객체 생성/삭제 자동 기록

  • 쿼리 실행 이력
  • GRANT/REVOKE 변경
  • CREATE/DROP 작업
  • 접근 실패 시도

규정 준수

주요 규정 자동 대응

  • GDPR: 개인정보보호 (EU)
  • HIPAA: 의료정보 (US)
  • SOC2: 서비스 조직 통제
  • CCPA: 소비자 프라이버시

데이터 분류

자동 메타데이터 수집

  • 태그 및 분류 체계
  • PII 자동 탐지
  • 민감도 레벨 관리
  • 데이터 카탈로그

3.4 데이터 공유 (Delta Sharing)

복사 없는 안전한 데이터 공유

Delta Sharing은 데이터를 복제하지 않고 원본 스토리지에서 직접 읽기하여 안전하게 공유하는 오픈 프로토콜입니다.

항목 Delta Sharing 전통적 ETL
데이터 복제 불필요 필수
실시간성 즉시 반영 배치 지연
스토리지 비용 절감 2배 이상
동기화 자동 수동 관리

주요 기능

  • 멀티 툴 지원: Pandas, Power BI, Tableau, Spark 등
  • 세분화된 권한: 테이블/파티션 수준 공유 제어
  • 감사 로깅: 외부 접근 추적
  • 오픈 프로토콜: Apache 2.0 라이선스

3.5 거버넌스 모범 사례

조직 구조 설계

  1. 계층적 구조
    • Metastore: 리전별
    • Catalog: 환경별 (dev/staging/prod)
    • Schema: 도메인별 (sales/marketing/finance)
  2. 명명 규칙
    • 일관된 네이밍 컨벤션
    • 예: {env}_{domain}
  3. 소유권 정의
    • Data Owner: 비즈니스 책임자
    • Data Steward: 품질/메타데이터 관리
    • Data Consumer: 최종 사용자

보안 운영 원칙

  1. 최소 권한 원칙

    필요한 최소 권한만 부여

  2. 정기 권한 검토

    분기별 접근 권한 재인증

  3. 이상 탐지 모니터링

    System Tables로 사용량 분석

  4. 자동 알림

    비정상 접근 패턴 자동 알림
